# 技巧 1：Mono 程序集字符串的原地重写（#US 堆 + ldstr 重映射）

> 适用：Unity **Mono 后端**（非 IL2CPP）游戏。台词/UI 文本不是运行时读外部文件，
> 而是编译进 `Assembly-CSharp.dll` 的字符串常量。
> 目标：把字符串替换成译文，且**文件大小不变、PE/元数据结构不动**。

---

## 1. 为什么是"原地重建字符串堆"

.NET 程序集里字符串字面量存放在元数据的 **`#US`（#USer strings）堆**，
IL 代码用 `ldstr 0x70xxxxxx` 指令按**堆内偏移**引用。

替换文本有两条路：

| 方案 | 问题 |
|---|---|
| 等长原地覆盖 | 中日互译长度几乎必然不同，且 `#US` 堆采用 UTF-16 + 长度前缀 + 压缩标记，无法等长 |
| 重建整个 `#US` 堆 + 重映射 `ldstr` 操作数 | ✅ 文件总大小可以保持不变（新堆更短时尾部补零），其余元数据一律不动 |

重建后**除了 `#US` 堆字节和各 `ldstr` 操作数 4 字节，其余任何字节都不应变化**——
这是最基本的自检。

---

## 2. 需要解析什么（最小集）

按顺序解析（可参考 dnlib/pefile 的结构文档，或手写）：

1. **PE 头** → sections（`.text` 等），定位 CLI header（`COR20`）；
2. **CLI header** → `MetaData` RVA → **元数据根**（`BSJB` 魔数）；
3. **元数据流**：`#~`（表流）、`#US`、`#Strings`、`#Blob` 的偏移与大小；
4. `#~` 表头：Valid Masks、各表的 RowCount（只需要少数几个表的行大小来**跳过**它们，
   无需理解每个表的语义——按 ECMA-335 的行大小规则推进即可）；
5. **方法体遍历**：对每个 MethodDef 行，按其 RVA 定位方法体
   （tiny/fat 头格式），线性扫描 IL：
   - opcode `0x72`（`ldstr`）→ 后跟 4 字节 token `0x70xxxxxx`，低 24 位即 `#US` 偏移；
   - 遇到 `switch` 等带内联数据的指令要正确跳过，避免把数据误当 opcode；
6. 收集全部 `ldstr` 引用 `(token文件偏移, #US偏移)`，并用 `#US` 解码出每个字符串
   （UTF-16，首字节为压缩长度标记；注意 `0x00` 结尾字节）。

> 提示：也可以用 Mono.Cecil（C#）或 dnlib 做同样的事；
> 纯 Python 手写的好处是零外部依赖、可控且便于做字节级校验。

---

## 3. 替换算法

```
1. 枚举旧堆中每个字符串 S_i（含偏移 off_i）
2. 构建 映射(S_i -> T_i)（命中的替换为译文，未命中的保持原样）
3. 重编新堆：顺序写出每个目标串（编码同 #US 规则），记录 new_off_i
4. 新堆总长 <= 旧堆总长时：原地写回，尾部补 0x00 到原堆大小（保持文件大小与后续偏移）
   （若变长：需要同时修正元数据根里的 #US 大小字段，并处理整文件偏移平移——尽量通过
    控制译文总长避免；常见做法是先统计再决定）
5. 把每条 ldstr 的操作数改写为 0x70000000 | new_off_i
6. 写文件
```

要点：

- **保持文件大小不变**是最低成本的方案：所有 section/元数据偏移都不用改。
- 换行风格跟随原文：原文用 `\r\n` 就写 `\r\n`（导出表里统一记成 ` / `，写回时还原）。
- **逻辑标记不能翻译**：若存在形如 `closeBox` 之类被代码做等值比较的"伪台词"
  （场景转场标记等），必须跳过。
- 编者注/占位行（如译文列以 `〔` 开头、空原文行）同样跳过。
- 多次补译要**幂等**：以"当前堆内容"为匹配源。已翻译的字符串日文原文已不在堆中，
  重跑旧表会全部"未命中"（无害）；补译用 `--only-extra` 之类的开关跳过主表。

---

## 4. 匹配：按内容而非 ID

导出表若带 ID，匹配仍然建议**按内容**做，原因：同一字符串可能被多个 ID 引用，
且 ID 在重建后会失效。匹配前做**归一化**：

```
norm(s):
  s.replace("\r\n", "\n").replace("\n", " / ")   # 换行统一为 " / "
   .replace("\u3000", " ")                       # 全角空格 → 半角
   .replace("\t", " ")                           # 制表符 → 空格
```

写回时按**原字符串实际使用的换行风格**还原（`\r\n` 或 `\n`）。
表内竖线要转义（`\|`），解析时只按未转义的 `|` 分列。

---

## 5. 校验（不做校验=盲改）

写盘前与写盘后各做一轮：

1. **字节差异审计**：与原文件逐字节比对，确认差异**只**存在于 `#US` 堆区间与
   `ldstr` 操作数（其余字节必须完全一致）；
2. **全量重解析**：把补丁结果当成一个全新程序集重新走一遍解析流程：
   - `ldstr` 数量与顺序一致；
   - 逐条比对"期望字符串 vs 实际字符串"；
   - **全部方法体 IL 重新线性解码**，0 异常（这一步能抓住绝大多数解析 bug）；
3. 文件大小与原文件一致。

---

## 6. 常见坑

| 坑 | 说明 |
|---|---|
| 换行风格 | 原文混用 `\r\n` 与 `\n`；写回必须跟随各自原文，否则 UI 换行异常 |
| 全角空格 | 日文文本大量使用 U+3000，导出时会被编辑器"看起来"变成普通空格 |
| `switch` 指令 | IL 线性扫描时必须按其内联长度跳过，否则解码错位 |
| 泛型/异常表 | fat 方法头含 ExceptionHandlingClause；只扫 ldstr 不需要解析它们，但**解码校验**时需按正确长度推进 |
| 逻辑标记 | `closeBox` 一类被代码等值比较的字符串绝不能替换 |
| 重复字符串 | 同一字符串被多条 ldstr 引用：映射按字符串内容建，逐条重映射即可 |
| 长度回退 | 若译文总长超过原堆：可先做全量统计，必要时允许堆变大（需同步改元数据根的 #US size 字段，并整体平移其后的流/数据——成本高，优先避免） |
